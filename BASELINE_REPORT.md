## 1. Build (`quarto render`)

**Result: succeeded** (exit code 0), all 23 files configured in
`_quarto.yml`'s `render:` list produced output.

Non-fatal items seen in the render log:

- `[WARNING] Citeproc: citation WHO2021 not found` while rendering
  `INFO_MINI_PROJETS/brain-tumor-classification-effcientnet.qmd`. The
  source cites `[@WHO2021]` twice, but `INFO_MINI_PROJETS/data_brain_tumor/biblio.bib`
  has no `WHO2021` entry. This is also why the rendered page has two
  dangling `#ref-WHO2021` anchors (see section 2).
- `ggrepel: 140/136 unlabeled data points (too many overlaps)` while
  rendering `ANALYSES_FACTORIELLES/acp-kmeans.qmd` - cosmetic plotting
  warning, not a functional bug.
- A handful of `joblib`/`loky` `resource_tracker` `UserWarning`s (leaked
  temp-folder cleanup) during a scikit-learn cross-validation chunk -
  benign Windows/Python housekeeping noise, not a real error.
- 13x `WARN: File '....html.md' was not found` printed right at the end of
  the render, for most of the `INFO_MINI_PROJETS/*`, `FORMATIONS/*`, and
  `ANALYSES_FACTORIELLES/acp-kmeans` outputs. This is Quarto's own
  post-render bookkeeping; the corresponding `.html` output was produced
  correctly in every case, so this looks like harmless internal noise
  rather than a real problem - but flagging it in case it's a sign of
  something to watch as Quarto is upgraded.

Two structural findings that matter for **future** CI runs (not fixed
here - see `TESTING.md` "Known gaps"):

- Several `.qmd` files (e.g. `Breast-Tumor-Article.qmd`, `work.qmd`)
  execute real `GridSearchCV`/cross-validation at render time (confirmed
  by watching dozens of `joblib` worker processes spawn during this
  render). Without Quarto's `freeze` cache committed to git (currently
  `.quarto/_freeze` is gitignored via the `/.quarto/` rule and no
  `freeze:` key is set in `_quarto.yml`), a from-scratch CI render has to
  redo this work every time, which is slow and heavy.
- `INFO_MINI_PROJETS/assistant_virtuel.qmd` depends on
  `speech_recognition`, `pyttsx3`, `pywhatkit`, `wolframalpha`,
  `googletrans`, `wikipedia`, and `pyaudio` - all installed on this dev
  machine, so it rendered fine here, but none of that is realistically
  installable/runnable headless on a stock GitHub Actions runner (needs a
  microphone/audio device, a paid Wolfram|Alpha API key, and drives a real
  browser). `qa-checks.yml` intentionally does not attempt to install
  these - see `TESTING.md`.

## 2. Broken internal links / images (`scripts/check_site.py`)

**102 errors, 29 warnings** against the freshly rendered `docs/`
(34 HTML files, 9 CSS files scanned). Grouped by root cause:

1. **Missing bibliography entry** (2 errors): `#ref-WHO2021` is linked
   twice on `INFO_MINI_PROJETS/brain-tumor-classification-effcientnet.html`
   but no such id exists on the page - direct consequence of the missing
   `WHO2021` bib entry above.

2. **Off-by-one relative path depth in a shared nav/sidebar snippet**
   (51 errors): `INFO_MINI_PROJETS/classi_bin_acp_kmeans_knn_logit/Breast-Tumor-Article.html`
   and `.../work.html` are both nested two directories under `docs/`, but
   the navbar/sidebar HTML baked into them uses single-`../` paths (as if
   they were only one directory deep). This breaks 5 image references
   (`djamal.png`, `logo.png`) and 46 navigation links (Home, Experience,
   Academic Projects, etc.) - every nav link and profile photo on these
   two pages is currently a dead link/broken image in the deployed site.

3. **Links to pages that are never actually rendered** (9 errors):
   `publications/stat_ml/index.html` and `publications/visualisation/index.html`
   link to `../../projet-traitement-donnees/report_writing/synthese-des-travaux.html`,
   `../../Projects/index.html`, and `../../about/academic-projects.html`.
   None of these exist anywhere in `docs/`. In the
   `synthese-des-travaux` case, only the `.qmd` source is present -
   `projet-traitement-donnees/` is listed under `resources:` in
   `_quarto.yml` (copied as-is), not `render:`, so Quarto never turns that
   `.qmd` into the `.html` these pages link to. `Projects/index.html` and
   `about/academic-projects.html` don't exist under any name in the
   built site.

4. **Missing third-party JS/CSS for pre-rendered pages** (30 errors):
   `projet-traitement-donnees/report_writing/Presentation/presentation-ptd.html`
   (a reveal.js slide deck) references `../../../site_libs/revealjs/...`,
   and `publications/stat_ml/index.html` / `publications/visualisation/index.html`
   reference `../../site_libs/quarto-listing/...` and hashed
   `bootstrap-*.min.css` files. None of `revealjs/` or `quarto-listing/`
   exist under `docs/site_libs` (or anywhere in the source tree - checked
   directly). These three HTML files appear to be static snapshots from a
   separate/older render that was checked in as a "resource" without its
   supporting asset libraries; as shipped, they're already broken on the
   live site today (missing styling/JS), independent of this render.

5. **Accessibility warnings - missing `alt` text** (29 pages, does not
   fail the check by default): every rendered page has at least one
   `<img>` without alt text; `ANALYSES_FACTORIELLES/acp-kmeans.html` is
   the worst at 14 images, most others have 1-12.

No broken *external* links were checked (out of scope by design - see
`TESTING.md`).

## What was and wasn't fixed

- **Fixed**: two real bugs in `scripts/check_site.py` itself, found while
  smoke-testing it against the committed `docs/` before this baseline run
  - a query-string-stripping bug that misreported a real, existing
  font file (`bootstrap-icons.woff?...`) as broken, and a false-positive
  where reveal.js's client-side slide routes (`#/introduction`) were
  checked as if they were DOM ids. Also taught it to recognize raw HTML
  include fragments (`project-shell.html`) so they aren't wrongly flagged
  for missing `<title>`/`lang`. These are fixes to the QA tooling, not to
  site content.
- **Not fixed**: everything in the punch list above - reported only, per
  the instruction to leave pre-existing content/build issues for a human
  to triage.

Abstract Analyzer

A submission and triage platform for scientific abstracts, generic enough for any conference, symposium, or themed-day organiser: online submission, real-time relevance scoring against the edition's theme, duplicate detection (always confirmed by a human), automated thematic clustering after the submission deadline, and an organiser dashboard.

Current status: single-tenant. The project will eventually become a multi-tenant SaaS (several organisers on the same instance), but that phase is deliberately deferred: the single-tenant product is built and validated first.

How it works

Submission An author submits an abstract for a given edition
Relevance score Real-time vector similarity against the edition's theme
Duplicate detection Automatic alert, final validation always by a human
Post-deadline clustering UMAP + HDBSCAN, hyperparameters re-optimised per edition via Optuna
Organiser dashboard Overview of submissions, detected themes, duplicates to resolve

Backend architecture

Strictly layered architecture: a layer never talks directly to the layer two levels below it (the API never calls a DAO directly). Every external dependency (database, vector store, embedding model) is hidden behind an interface, swappable via configuration without touching the business logic.

api (FastAPI endpoints, validation, zero business logic)
services (business logic, orchestrates the DAOs/providers)
dao (interfaces + SQLAlchemy implementations)
domain (pure business entities, no framework dependency)
Where the code stands: the domain, the DAO/Provider interfaces, and the ORM models are written. Only one concrete implementation exists so far (the MySQL abstracts DAO); the rest (remaining DAO implementations, vector store, embedding provider, services, API layer) is still to be written following the same pattern.

Tech stack

Backend: Python, FastAPI (domain / dao / services / api layered architecture) · Relational database: MySQL locally, PostgreSQL + pgvector targeted for deployment · Vector store: ChromaDB locally, pgvector in deployment · Embedding: SPECTER2 (similarity between scientific documents) · Clustering: UMAP, HDBSCAN, Optuna · Frontend: React (skeleton) · Tools: uv, Alembic, Docker, pytest
